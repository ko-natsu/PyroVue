## Phase C — physical gate: partial owner verification

Historical source-handoff inventory from the earlier hardware-unavailable session:

```json
[{"port":"COM1","description":"Communications Port (COM1)","hwid":"ACPI\\PNP0501\\0"}]
```

At that earlier checkpoint no USB ESP board was visible and no device mutation was performed.

The owner completed bring-up walkthrough steps 1–5 and then uploaded the M2 firmware. Owner-provided `/api/info` reports device `aca704126810`, boot `d60e5e28679d3fa4`, flash 16,777,216 bytes, usable PSRAM heap 8,385,783 bytes (largest free block 7,995,380), and mounted LittleFS label `spiffs`: total 10,354,688, used 16,384, free 10,338,304 bytes. Logging is idle with no error; Start requires 2,416,640 free bytes. The MAX31855 is not wired. Exact board revision and explicit readback/persistence remain unverified.

The heap value exposed an incorrect exact-8-MiB comparison in `RunArchiveStore::checkStart()`: Arduino's `ESP.getPsramSize()` returns allocator capacity, not chip capacity. The correction uses `esp_spiram_is_initialized()`/`esp_spiram_get_size()` for the physical profile check, reports `psramHeapBytes` separately, and prints Start readiness via serial reconnect/`i`.

The correction built and uploaded successfully on COM6 (ESP32-S3 revision v0.2, MAC `ac:a7:04:12:68:10`). Actual serial `i` output: `flash=16777216 psram=8388608 fs=mounted`, total 10,354,688, used 16,384, largest free PSRAM block 7,995,380, `start=ready`, usable PSRAM heap 8,385,943. This exercises the real Start preflight without allocating a run ID or starting a run. Firmware-only upload; no filesystem image or format.

M3 subsequently verified file persistence using the real archive rather than another scratch-file harness: run 1, origin boot `1f52201c6875b89d`, retained all 31 records/61 acquired identities and its original protocol-2 provenance across firmware uploads/reboots. HTTP samples matched all CRC-decoded stored values. See [M3 handoff](n16r8-m3.md).

Remaining procedure (firmware-only updates; no repeat `uploadfs`):
1. If completing the remaining explicit memory gate, exercise PSRAM pattern write/readback. File persistence is already demonstrated by real run-1 readback; do not repeat filesystem provisioning.
2. When the MAX31855 is wired, record valid temperature and open-probe fault readings at 1 Hz. The sensor does not block further M2 work.
3. Record that physical evidence here before marking M1 complete. Keep the default on Feather until M7.
