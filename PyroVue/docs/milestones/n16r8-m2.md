## Phase A implementation

Changed files and symbols:

- `lib/RunLog/RunRecorder.{h,cpp}`: implements the frozen `reset`, `select`, `finish` methods with private fixed-size state and no allocation. First real acquisition is selected immediately, then the first acquisition at least 2000 ms after the previous selected reading. Unselected latest acquisition is emitted once on finish with terminal bit 0. Every acquired timestamp is examined; `dt > 1500 ms` sets acquisition-gap bit 1 on the next record. Faults between selections are ORed into `intervalFault`, including the current acquisition. Temperatures retain float32 bits, including negative zero and NaN payloads. No interpolation/catch-up records or fabricated sensor-fault bits.
- `lib/RunLog/MarkerReducer.{h,cpp}`: implements all frozen methods. Input is the **whole caller-owned PVE1 journal**, including its 16-byte header, at a stable address. Prefix growth is append-only, at complete-frame boundaries, up to 262144 bytes. Each `ingestNext` call reduces at most `min(maxFrames, 8)` frames. CRC/UTF-8/JSON encoding, required field types/ranges, global revisions, lifecycle and marker transitions are validated before publishing an event. Invalid input preserves the preceding valid revision/count/index state and makes readiness false. Stored note text is preserved, not re-trimmed.
- Reducer marker and operation indexes each have 4096 compact 32-bit offset/hash entries. Collisions compare decoded IDs. Tombstones retain consumed marker IDs and revisions; operation lookup returns the original domain payload and persisted result, not the marker's latest edited state. Different markers use their own latest mutation revision as `baseRevision`. Notes may follow `run.ended`; another lifecycle end is rejected.
- The reducer lazily allocates one approximately 56 KiB index/JSON scratch block, explicitly using `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT` on ESP32 and host allocation for native execution. ArduinoJson uses a reusable bounded 24 KiB arena; there is no per-event heap allocation, per-index note buffer or journal copy. Reset reuses the block; destruction releases it. The owning reducer is noncopyable. The future store must supply its single stable PSRAM journal cache; do not put a full-run journal or index in internal-RAM globals.
- `test/test_recorder/test_main.cpp`: 12 Unity behavior cases for cadence, accumulated faults, gap threshold/jitter, no catch-up, finalization, reset/run isolation, invalid/idle inputs, 24-hour bounds and exact float bits.
- `test/test_reducer/test_main.cpp`: 23 Unity behavior cases for bounded ingestion/growth, lifecycle/marker transitions, original-operation replay, unchanged outputs on failed lookup, Unicode/500-scalar limits, zero/untimed notes, real hash collisions, corrupt tails, invalid JSON/Unicode and reset/error isolation.
- `platformio.ini`: native ArduinoJson dependency pinned to `7.4.3`, matching the installed firmware dependency used for this implementation.

Unchanged contracts: archive schema **1**, PVR1/PVE1 formats **1**, acquire interval **1000 ms**, record interval **2000 ms**, maximum elapsed **86400000 ms**, record budget **43202**. Wire remains **v2**, and Feather remains the default environment until the later migration gates pass. The recorder marks timing holes, not acquired-sequence jumps alone. Invalid/out-of-window acquisitions do not displace the retained latest in-range reading or contribute faults.

`lookupMarker` and `lookupOperation` leave outputs untouched on failure. Tombstone outputs have no invented note/timestamp. Header corruption, frame corruption/truncation or semantic violations latch `CORRUPT_RUN` until reset; allocation failure latches `STORAGE_UNAVAILABLE`. Invalid prefix-growth arguments return `INVALID_REQUEST` without changing the bound prefix. A header-only prefix can be ready at revision zero during staged loading; the future store still must require its initial lifecycle record before accepting a prepared run.

## Runtime proof — host disk and independent consumers

A throwaway gnu++11 consumer compiled the actual recorder, reducer, PVR1/PVE1 codecs and CRC with `-Wall -Wextra -Werror`. It wrote and fsynced real POSIX files, reopened them, and exercised:

1. Acquisitions at 1000..6000 ms produce acquired sequences 1, 3, 5 and terminal 6 with logged sequences 1..4. Negative zero, an intervening fault and terminal identity survive selection and binary decoding. An 11-byte incomplete record tail stays on disk and is excluded from the validated prefix.
2. Acquisitions at 1000/2000/4000 ms flag the missed acquisition despite a selected-record delta of only 3000 ms.
3. An accelerated full-day stream produces **43201 records**, including the final 86400000 ms terminal reading, below the 43202-record budget. This is virtual elapsed time, **not a 24-hour device soak**.
4. A six-revision journal is replayed first through revision 3, then extended through revision 6. Create/edit/end/delete/post-fire untimed note produce the correct current marker, tombstone and count. Looking up the original create operation still returns its original zero timestamp and Unicode/quoted/multiline note after subsequent edits/deletion.
5. Independent Python `struct`, `zlib` and `json` processing verifies both file headers, every record/frame CRC, exact original sample identities/values and the final note. Node passes those independently decoded files through the existing `parseSamplesPage` / `parseEventsPage` validators with fixed identity/cursor contexts.

Observed output:


These are real library/host-disk/consumer checks, **not LittleFS, NVS, HTTP, browser-surface or physical durability proof**. No frontend surface changed in this phase.
