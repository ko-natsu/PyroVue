# N16R8 kiln logging and run export migration

## Context
Migrate the active PyroVue application to an ESP32-S3 DevKitC-1 N16R8, headless with the existing browser UI. Record kiln runs on-device regardless of browser connectivity, retain multiple runs until manually deleted, and download complete recorded measurements plus timestamped notes/markers in a portable ZIP. Acquire at 1 Hz, persist unfiltered readings every two seconds, retain five minutes of recent 1 Hz data, and use five-second aggregates for the full-run graph. The user selected a 24-hour maximum reservation including cooling; logging ends explicitly at that limit while temperature monitoring continues.

### Identity, sample selection, and analysis
`deviceId` is the stable lowercase 12-hex STA MAC read using `esp_read_mac(..., ESP_MAC_WIFI_STA)`. `bootId` is a new random 16-hex value generated on every boot, not a per-second NVS write. A run is identified by `(deviceId, runId)`; its metadata stores originating `bootId`. Numeric runId is monotonically persisted and never reused while a corresponding archive/staging directory exists. On boot load the maximum of NVS runId and validated archive/staging IDs. A failed NVS save rejects Start instead of silently accepting an identity that may be reused.

`TempSample.seq` remains the 1 Hz acquired sequence. The new `LoggedSample` contains `{logSeq,acqSeq,ms,tempC,fault,intervalFault,flags}`. `logSeq` starts at 1 and is consecutive in the recorded log; `acqSeq` preserves original acquisition identity and may advance by two normally. Do not merge a logged record into the live raw map under logSeq.

Select the first acquired run sample immediately, then the first sample whose `ms - lastLoggedMs >= 2000`. Use actual acquisition timestamp/value; never interpolate or generate catch-up samples. On normal stop/limit, append the latest acquired sample if its acqSeq is not already selected, with terminal flag bit0. `intervalFault` ORs faults since the previous selected sample, including the current sample, so a one-second fault between persisted readings is not erased. A failed sensor read produces a faulted/non-finite acquired reading rather than consuming no identity. Recorder examines every acquired timestamp: dt>1500ms sets `flags` bit1 (`acquisition_gap`) on the next selected/terminal record. Never use a fabricated thermocouple fault bit for missing time. Before each sensor tick, enforce the 24h boundary; no sample with ms>86400000 enters that run. Limit finalizes the latest already-acquired in-range sample and reports endElapsedMs=86400000.

N16R8 recorded-analysis points={kind:'raw',runId,seq:logSeq,acqSeq,ms,tempC,fault:(fault|intervalFault),sampleIntervalMs:2000,source:'recorded',gapBefore:Boolean(flags&2)}; live points retain acquired seq/interval1000/source=live. Cone/saved analysis uses recorded points, current rate uses live points; never mix their sequence domains. Raw continuity requires consecutive seq, !next.gapBefore, positive dt<=1.5*sampleIntervalMs. Without explicit interval keep legacy behavior. acquisitionGaps counts durable gap-bit records, not fabricated missed measurements; recovery derives same count. Do not bridge invalid readings/gaps/tails. Full preservation means ALL selected2s records and saved annotations, not every transient1Hz reading; five-minute high-rate history is explicitly nondurable.

N16R8 filtering is not added: latest live readout unfiltered/faults immediate. Five-second graph buckets use kind=coarse/resolutionMs=5000, average/min/max finite records and OR actual faults; origin=floor(ms/5000)*5000. Graph-only gap=true if containing gapBefore or dt>3000ms including across buckets; empty buckets also break. Flush/no connecting line or continuous band across gap bucket; extrema may remain cached. No fabricated sensor fault. Last300s live1Hz overlay suppresses overlapping graph buckets only, never analysis records; saved views have no live overlay. Current header rate always uses current device live samples, even viewing an old run. Saved-run rate regions and N16R8 cone use recorded samples. Monitor capability=false retains existing TelemetryStore raw/coarse cone/rate path and legacy continuity, never references omitted archive modules; use its actual hello cadence. Existing Orton table/model unchanged.
